## Context

The terminal is the centrepiece app — the thing that makes "this is an operating
system" a claim rather than a theme. Design doc §2 sets the shape: xterm.js
handles emulation, and a small command dispatcher on top tokenises input, looks
it up in a command table, and reads/writes kernel state through the syscall
boundary. §4 puts ~8 commands in Phase 1; §2 says explicitly not to hand-roll
emulation.

Everything it needs now exists. The VFS is populated from real content with a
stable path layout, so `ls`, `cd`, and `cat` have something true to walk. The
syscall boundary is the only way it will reach any of it.

This is also where the **minimize-unmounts-the-app** gap stops being theoretical
— `wm/Window.tsx:56` returns `null` for a minimized window, which would throw
away scrollback, cwd, and a half-typed command line. It gets fixed here.

**Out of scope:** piping and redirection (design doc §2 calls it a scope-creep
magnet), persisted history, tab completion, the file viewer, games.

## The shape: the shell is not the terminal

The one structural decision. **The command layer has no xterm dependency at
all.** It is plain TypeScript that takes a line and a context and returns
output:

```ts
runCommand(line: string, ctx: ShellContext): ShellResult
// ShellContext = { kernel: KernelAPI, cwd: string }
// ShellResult  = { output: string[], cwd: string, cleared?: boolean }
```

xterm is one possible *device* attached to that shell, not the shell itself.
This is the design doc's mechanism/policy split applied one level down, and it
buys the same thing it bought in the kernel: **every command is unit-testable in
a bare node environment**, with no DOM, no terminal, and no component harness.

The keystroke-to-line logic is separated for the same reason. `lineEditor.ts` is
a pure state machine — `(state, input) => [state, effects]` — so cursor
movement, backspace-mid-line, and arrow-key escape sequences get tested directly
instead of being poked at through a rendered terminal.

```
apps/terminal/
  Terminal.tsx     ← xterm host. Thin: wire input, print output, fit on resize
  lineEditor.ts    ← pure keystroke state machine
  shell.ts         ← tokenise, dispatch, format errors
  commands.ts      ← the command table
```

## Decisions to record

**D-013 — a minimized window stays mounted and is hidden with CSS.**

`Window.tsx` currently returns `null` when `state === 'minimized'`, unmounting
the app. Change it to render as normal with `display: none` on the frame.

*Why.* A terminal that forgets its scrollback, its cwd, and the command you were
halfway through typing is not a terminal. This is the first app whose state is
worth anything.

*Cost, and it is one `docs/gotchas.md` explicitly anticipated* ("too many windows
open with complex DOM apps inside — each one is a live component tree, not a
frozen screenshot"). Minimized windows now hold live React trees. `display: none`
means no paint and no layout, so the cost is memory rather than frame time, and
that is the right trade for a terminal. If an expensive app ever wants the old
behaviour, the escape hatch is a manifest flag rather than a WM change.

**D-014 — `proc.list()` is added to the syscall boundary.**

`ps` needs to enumerate processes and the API has no read path for the process
table — only `spawn`/`kill`/`focus`. Adding `proc.list()` behind a new
`proc.list` permission, returning a snapshot array.

*Why it's worth noting:* it is the first genuinely *new* capability the boundary
has grown since it was designed, and it came from an app needing it rather than
from guessing up front. That is the registry/manifest model working as intended.

**In-session history is included; persisted history and tab completion are
not.** Design doc §4 puts "command history/autocomplete" in Phase 2, and that
still holds for anything that survives a reload or completes a path. But a
terminal where the up arrow does nothing feels broken within about five seconds
of use, and an in-memory ring is ~15 lines. Flagging the small scope addition
rather than making it quietly.

## Commands

Ten, all thin wrappers over the syscall boundary. Unknown command, wrong arity,
and bad paths each produce a one-line error in the shape a UNIX user expects
(`cat: /nope: No such file or directory`).

| Command | Behaviour |
|---|---|
| `help` | the table below, generated from the command table itself |
| `pwd` | print cwd |
| `ls [path]` | children with type markers — `dir/`, `app*`, plain files |
| `cd [path]` | resolve against cwd; bare `cd` goes to `/`; error if not a directory |
| `cat <path…>` | file contents; error on a directory or an asset-backed node |
| `open <path>` | spawn an app node's app, or focus it if already running |
| `ps` | pid, app, state, title — via the new `proc.list()` |
| `kill <pid>` | `proc.kill`, including the terminal's own pid |
| `clear` | clear the screen |
| `echo <args…>` | print |

`open` on a *file* is a deliberate dead end for now: it prints
`open: no application registered for text/markdown — try 'cat'`. The file viewer
is the next app, and it will register itself as the handler.

Path resolution reuses `resolvePath`/`normalize`/`resolve` from `kernel/vfs.ts`
— they were written for exactly this and must not be reimplemented here.

**Permissions:** `['fs.read', 'proc.spawn', 'proc.kill', 'proc.focus',
'proc.list']`. No `fs.write` — nothing writes without redirection.

**cwd is app state**, held per terminal instance, not in the kernel (design doc
§8.4: app-internal state is local to the app). Two terminals have two working
directories, which is what a second terminal is *for*.

## Build steps

1. `pnpm add @xterm/xterm @xterm/addon-fit` — note the scope change from the
   design doc's `xterm.js`; the unscoped `xterm` package is the old one.
2. `kernel/api.ts` — add `proc.list()` + the `proc.list` permission; extend
   `ALL_PERMISSIONS`.
3. `wm/Window.tsx` — D-013: render minimized windows hidden instead of
   unmounting.
4. `apps/terminal/lineEditor.ts`, `shell.ts`, `commands.ts` — pure, tested
   first.
5. `apps/terminal/Terminal.tsx` — xterm host:
   - `import '@xterm/xterm/css/xterm.css'`; it code-splits with the app since
     the manifest is already `ssr: false`
   - `FitAddon`, refit from a `ResizeObserver` on the container, rAF-debounced
     and **skipped when the box is 0×0** — which is exactly what a minimized
     window now is
   - the observer means the terminal never subscribes to the process table; it
     reacts to its own box, and the WM stays unaware it exists
   - `dispose()` on unmount
6. `registry/index.tsx` — register the manifest; `content/index` needs no change
   since `/apps` is built from the registry.
7. Banner on spawn: kernel version, `help` hint.

## Verification

**Unit** (`pnpm test`, extend to `apps/**/*.test.ts`) — the bulk of the
confidence, all in node:

- every command against a seeded VFS and process table, success and failure
- `cd` relative, absolute, `..` past root, into a file (must error)
- `cat` on a directory, a missing path, an asset-backed node with `src` and no
  content
- `ls` marks dirs, apps, and files distinctly
- `open` spawns for an app node, errors for a file
- `ps`/`kill` against a populated process table; `kill` on an unknown pid
- unknown command and wrong-arity errors
- line editor: insert mid-line, backspace at column 0, Left/Right/Home/End,
  history up past the oldest entry and back down past the newest

**End-to-end** (`scripts/verify-terminal.mjs`) — real Chrome, typing real keys:

- spawn the terminal, run `ls /projects`, see both project slugs
- `cd /papers` then `ls` shows the draft — the OS sees what the web does not
- `cat /home/about.md` prints content read through the boundary
- `open /apps/sysinfo` spawns a second window
- `ps` lists both pids
- **the D-013 check:** type a partial command, minimize, restore — scrollback,
  cwd, and the half-typed line all survive
- resize the window and confirm the terminal refits (cols change) without the
  drag-commit contract breaking

**Regression:** `pnpm verify` 17/17 and `pnpm verify:content` 13/13 must both
still pass — D-013 touches `Window.tsx`, which the WM checks cover directly.
