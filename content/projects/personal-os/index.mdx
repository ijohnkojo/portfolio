## Overview

{/*
  - a mock operating system that runs in the browser, at /os
  - built on the UNIX split: the kernel provides mechanism (a virtual
    filesystem, a process table, an event bus); everything else — window
    manager, shell, apps — is policy on top, and swappable
  - apps never touch kernel state directly: every call goes through a syscall
    boundary that checks the permissions the app declared in its manifest
  - its filesystem is the site's own content, read from the same files on
    disk as the web pages — `cat` a writeup and you get its source
*/}

## What it does

{/*
  - windows: drag, resize, minimize, maximize, snap to halves, tile
  - a shell with thirty-one commands, pipes and redirection (| > >>), tab
    completion, and history persisted as a file (/home/.history)
  - seven apps: terminal, files, editor, viewer (markdown, JSON, PDF, images),
    settings, about, sysinfo — each lazily loaded, each in its own error
    boundary (an app that crashes shows a "segmentation fault" panel and the
    rest keeps running)
  - a desktop whose icons are a view of a real directory, /desktop — so
    `cp x /desktop` makes an icon appear
  - settings are a file too (/home/.settings): writing it repaints the desktop
  - the session survives a reload: open windows, positions, and anything you
    wrote, stored in localStorage behind a versioned schema
*/}

## How it's built

{/*
  Stack: Next.js 16, React 19, TypeScript, Tailwind 4, Zustand (vanilla — the
  kernel imports no React), react-rnd for windows, xterm.js for the terminal.
  Tested with Vitest: 463 unit tests for the OS, all in bare node with no
  browser; plus six scripts that drive real Chrome.

  Yours to choose what to explain. The decisions log has 36 entries; the ones
  that carry the most weight:
  - D-001 the kernel has no React import, which is why its tests run in node
  - D-002 / D-006 a window drag commits to state only when the drag ends, so
    nothing re-renders while a window moves
  - D-010 one read of content/ feeds both the web pages and the filesystem
  - D-023 the shell cannot touch the window manager; it emits an event and
    the window manager decides
*/}
