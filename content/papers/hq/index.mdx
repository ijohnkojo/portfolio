## Overview

{/*

## Tradeoffs

{/*
  From the upstream README + your slides. These are design facts, not yours,
  but the entry is better for naming them:
  - pickup latency bounded by poll interval, ~1s
  - no locality-aware scheduling — worker takes next task, not nearest
  - worker dies holding a claimed task → ~30s heartbeat timeout, marked lost,
    NOT requeued. Ownership IS tracked (workers:running:{workerId}); nothing
    acts on it. You proposed requeue-on-timeout.
  - in exchange: cheap networking, workers join/leave freely (suits
    opportunistic HTCondor slots), durable stop-and-resume
*/}
